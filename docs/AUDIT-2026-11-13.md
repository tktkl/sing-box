# 安装主机与客户端兼容审计

审计日期：2026-11-13。通过 SSH 对已安装主机进行只读检查，并从隔离容器发起真实客户端连接。未修改主机配置、凭据、服务或其他项目的 Nginx/Xray 资源。

## 运行配置

- 管理脚本版本为 0.1.1，服务端内核为 1.14.4，与当日 [sing-box 官方最新稳定版](https://github.com/SagerNet/sing-box/releases/tag/v1.14.4) 一致。
- 当前为一个 VLESS-REALITY 节点，使用 Vision flow，SNI/握手目标为 `apps.mzstatic.com`。`sing-box check` 成功，systemd 服务持续运行且无自动重启记录。
- 运行配置不包含客户端版本上下限，也未设置 `min_version`、`max_version` 或 REALITY 时间偏差限制。TLS 版本字段与客户端应用版本字段含义不同，不能相互替代。
- 生效配置、全局设置、证书及网站记录没有发现 `YOUR_*`、`CHANGE_ME`、`/path/to/`、`preview-certificate` 等未替换占位符。
- 安装主机的配置编译器、节点逻辑、基础模块和交互模块摘要与 v0.1.1 源码一致。
- 两个预设握手目标 `apps.mzstatic.com`、`xp.apple.com` 均在该主机通过 TLS 1.3 及证书验证。

当前 REALITY 无需自有证书，因此节点记录中空的 `domain`、`certificate_id` 和证书列表并非遗漏。直连出口不需要远端 `server`；摘要中的 `null` 不是未替换的远端地址。内部节点模型保留的其他协议字段不进入该节点的运行配置。特殊地址段中的文档示例网段属于拒绝规则，不是代理目标。

## 新旧客户端实测

| 1.11.15 | 通过 | HTTP 204 | 通过 |

上述为实际 VLESS-REALITY Vision TCP/UDP 通信，不只是语法检查。客户端配置中没有应用版本上下限；没有关闭证书校验，也没有更改现有服务以适配测试。

测试只证明表中版本与该节点的组合，不能推广为所有历史版本、所有协议或全部第三方客户端均通过。AnyTLS 在 [官方文档](https://sing-box.sagernet.org/configuration/inbound/anytls/) 标记为后续新增功能；不具备对应协议实现的旧客户端无法使用它。Shadowsocks 2022 与传统 AEAD 方法也应按客户端已有能力选择。

## 最新规则核对与边界

- DNS 使用新式 `{type:"local"}` 结构，规则集采用本地 SRS，路由使用独立 `sniff`、`resolve`、`reject`、`route` action，符合 [迁移文档](https://sing-box.sagernet.org/migration/) 中的新格式。
- REALITY 的握手地址、私钥及 short ID、VLESS Vision flow 符合当前 [TLS](https://sing-box.sagernet.org/configuration/shared/tls/) 和 [VLESS](https://sing-box.sagernet.org/configuration/inbound/vless/) 配置字段。
- 不需要把官方示例中的每个空字段都写入配置。证书由外部 Certbot 管理，未使用已废弃的内联 `tls.acme`。
- 该主机当前只有 REALITY；没有把本次检查表述为该主机的 Certbot、Cloudflare 或所有 TLS/QUIC 协议现场验收通过。其余组合的隔离测试记录见 [VERIFICATION.md](VERIFICATION.md)。
- 服务端配置必须能被选定内核解析。固定服务端内核和“不限制连接客户端版本”是独立行为，不能通过直接删除服务端检查来声称任意旧内核都可运行当前配置。
